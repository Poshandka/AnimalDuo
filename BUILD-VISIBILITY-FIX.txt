iPad/iPhone presentation-lifecycle follow-up (2026-10-30)

Read BUILD-COMFORT.txt for the full source, dependency, preparation and unsigned iOS build procedure. The presentation change after the Comfort release is ACNHCompanion.swift: published visibility is externally read-only, the root presentation callback uses the polling-owner transition, hidden transitions cancel the timer/native command work and show transitions restart polling with an immediate snapshot read. Identical physical-controller/artwork notifications do not reschedule timers.

This is a universal unsigned iPad/iPhone update. Preserve the prior bundle/signing identity when cover-installing. The Apple native adapter also publishes host.press immediately and releases it independently of passive page sampling, with generation-checked cancellation. A separate presentation generation discards data samples that cross a hide/resume transition, so old module input cannot return after the companion is shown again. The updated Mac package includes that shared fix. Graphics, shaders, manifest, game files and the save engine remain unchanged. No new target-device performance claim is made.

validation/visibility reproduces the old C-entry-point failure against a synthetic native engine and checks the fixed production UIKit path. Ad-hoc sign these local test apps only. Launch each with VISIBILITY_REPORT set to an external output JSON path. Both exit after writing their results. The old app must report FAIL for missing native visibility/cancellation/immediate-refresh behavior; the fixed app must report PASS for all six checks. No game, user save or cloud folder is read/written by this fixture.

The native input test deliberately blocks sampling to reproduce the previous missed short pulse. It checks immediate delivery, independent release, preserved module input, newer-pulse protection visibility cancellation and stale-sample rejection after hide/resume.
