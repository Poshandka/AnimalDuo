Apple long-session cache and diagnostic update (2026-10-30)

Read BUILD-COMFORT.txt for complete game preparation, dependencies and unsigned iOS packaging; BUILD-VISIBILITY-FIX.txt and BUILD-FRAME-OPTIMIZED.txt document the preceding updates. No game files, shaders, resident data, saves or cloud configuration are changed here.

Production changes
dm/host/companion_apple.mm expires the one-second negative-image cache in insertion order and retains at most 512 misses. Decoded native art adds a 1024-entry NSCache target alongside its existing 64-MiB cost target. The count and cost targets are advisory OS cache policies, not a hard process-memory limit.
dm/ios/Sources/EdenCompanion.swift keeps the visible image working set independently of discardable warm art. The remaining portion of the 96-MiB target goes to warm images, with a 1024-entry target. Pins leave the visible set when keys change or the companion hides; memory trimming releases both stores before reloading. Live failure/backoff state follows current requested keys. Pending image loads do not poll an expired retry deadline. A newly missing asset can schedule an earlier retry, and superseded tasks cannot erase a new generation's scheduler state.
dm/host/performance_apple.m adds frame_max_ms, intervals_over_50_ms, intervals_over_100_ms and gap_max_ms to the default-off, thirty-minute presented-time recorder. Intervals over two seconds remain separate gaps; app visibility is needed to interpret them. No pacing or game-time behavior is changed.

Cache controls
The production Python command is python3 -m unittest dm/ios/tests/test_companion.py. Its test target appends eden_images_check.swift to the renderer so production-private types remain private in the real app. It covers forced discardable-cache eviction, visible-image retention, leaving a page, hiding, trim/reload, late results, failure scope, earlier retry deadlines and cancellation generations.
validation/long-session/ImageCacheCheck.swift is the old/new synthetic-pixel control. Append it to either EdenCompanion-before.swift or the production renderer, compile with ACNHCompanion.swift and dm/ios/tests/companion_stub.m, using Swift 5, -O, -parse-as-library, the dm/host/companion_apple.h bridge, SwiftUI and AppKit. Pass an external result JSON path. Old art disappears after its NSCache is purged; fixed current-frame art remains without another load.
NegativeCacheCheck.mm compiles with either companion_apple-before.mm or the production adapter. Include dm/host and dm/host/tests, define DM_HAS_COMPANION=1, use Objective-C ARC/C++20 and link Foundation, CoreGraphics, Metal and ImageIO. The preserved adapter_contract-before.mm supplies the synthetic module. Exit 48 is the expected old 10,000-miss failure; the fixed adapter exits zero. Tiny-image retention is measured as an NSCache target behavior on this Mac, not promised as an OS hard limit.

Sustained route and limitations
The local native Mac test uses a separate bundle, a copy of the reference island and no cloud bookmark. After player readiness it runs for thirty minutes, selects six pages every twenty seconds, requests at most thirty-two module-image keys per page and opens/closes the game pockets on DIY phases. Physical footprint and module counters are sampled about every five seconds. Image requests and samples must finish without errors, and the original reference save's complete file fingerprint must remain unchanged.
The baseline and candidate do not have identical visibility conditions. The baseline lost focus and has incomplete drawable presentation coverage. The candidate helper records AppKit activity/main-window flags and temporarily requests that idle display sleep be disabled while its own process lives. A false main-window flag is not proof that every window is invisible. Actual drawable presentedTime callbacks are the frame evidence; gaps are kept separately. Never infer a percentage memory or FPS improvement from these two traces.
The recorder stops thirty minutes after its first valid displayed frame, which includes startup. The process route continues thirty minutes after player readiness, so its final minute can outlast the presentation report. A sampled footprint maximum is not an instantaneous process high-water mark. This route does not validate physical iPad/iPhone/M2 behavior, device battery/thermals, cross-island visits or prolonged building/multiplayer sessions.

Packaging and reproduction
The current sources rebuild the unsigned universal iPad/iPhone IPA and a generic arm64/Apple-m1-baseline native Mac app. Preserve the original bundle identities and the documented DEFLATE repacker. Only local Mac validation fixtures and the native Mac distribution are ad-hoc signed; no iOS player device is signed or installed. The native startup comparison still invokes the regular scripts/regress.py through the exported fresh-host app wrapper. It checks the only local game, not the Swift UI or long-session performance gain.
The source tree contains the actual cache, timestamp and input tests. Validation summaries and the synthetic control sources are under validation/long-session. SoakProbe.mm is instrumentation for a disposable native Mac game process (DYLD_INSERT_LIBRARIES and PROBE_ROOT); game resources and copied saves must stay outside this source tree. SoakProbe-baseline.mm preserves the earlier helper. Never point either at a real local/cloud save.
