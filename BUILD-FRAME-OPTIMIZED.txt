Apple companion immutable-template update (2026-10-30)

BUILD-COMFORT.txt contains the full game/dependency/preparation and unsigned iOS build procedure. BUILD-VISIBILITY-FIX.txt documents the preceding presentation and shared native-input fixes. This follow-up changes only EdenCompanion.swift in production: immutable widget instances are expanded once when EdenManifest loads, while each EdenFrame freshly evaluates live bindings, repeat counts, visibility, coordinates, clipping, paint order and hits. The one-pixel waiting-image prewarm omission and repeat limit are preserved. The manifest, game files, shaders, save engine and native Mac executable are unchanged. The previous verified Visibility-Fix Mac ZIP is reused byte-for-byte.

Reproduce the optimized frame microbenchmark on Apple Silicon with Xcode from this source root:
  xcrun clang -fobjc-arc -c dm/ios/tests/companion_stub.m -o /external/scratch/stub.o
  xcrun swiftc -O -swift-version 5 -parse-as-library -import-objc-header dm/host/companion_apple.h dm/ios/Sources/ACNHCompanion.swift dm/ios/Sources/EdenCompanion.swift validation/frame/FrameBenchmark.swift /external/scratch/stub.o -framework SwiftUI -framework AppKit -o /external/scratch/FrameBenchmarkNew
Build FrameBenchmarkOld with validation/frame/EdenCompanion-before.swift in place of the production renderer. Run each executable with dm/third_party/eden_duo/acnh/manifest.json and an external output JSON path as its two arguments. Wrap with /usr/bin/time -l to capture the microbenchmark process's peak footprint. Use an old/new/new/old order and run without other builds or game processes. The benchmark uses synthetic values and a per-frame autorelease pool; it does not draw, read guest memory or touch any save/cloud folder.

Compile FrameContract.swift in place of FrameBenchmark.swift, then compare the old/new output JSON. It compares six selected pages across eight module states and four local states, including waiting/title/version/error, pocket counts, DIY/modal values, scroll, themes and selections. Complete frame node dictionaries, rects, clips, sources, text and center-point hits must match. Production companion_model_check.swift separately changes bindings/counts after constructing a shared manifest; the previous frame must retain its original values. The original scrollbar Canvas pixel test is also recompiled against the new renderer.

The two interleaved local M4 measurements reduce the median frame-construction step from about 20 to 2.68 ms on pockets and 27 to 2.27 ms on DIY. The one-time manifest initialization in those processes rises from 12-29 to 77-103 ms; peak process footprint rises from about 10.3 to 18.6 MB. These are bounded microbenchmark results, not full UI, whole-game frame-rate or iPad energy measurements. Physical iPad/iPhone and thirty-minute thermal/battery validation remain open.

Unsigned iPad/iPhone packaging preserves the prior bundle identity and all game/layout/shader/catalog resources. Use the documented DEFLATE repacker for the existing side-loading tool. No device is signed or installed by this workflow. Validation logs, baseline renderer and comparison programs are in validation/frame. The fresh-host startup regression still uses the normal scripts/regress.py and only the locally installed game; it does not exercise the Swift companion or establish a renderer speedup.
