Apple Animal Crossing 3.0.3 measured shader-preparation update (2026-10-30)

Read BUILD-COMFORT.txt and BUILD-LONG-SESSION.txt for complete game preparation, dependencies, existing features and unsigned iOS packaging. This update changes the content-key prewarm seed and the game note. It changes no translator, shader libraries, renderer settings or compiled gameplay/UI code.

Cause and fix
The original seed covers the fresh-island setup route. The two previous copied-island thirty-minute routes encountered additional libraries and render/compute pipeline states that the seed never named. The existing MTLDevice renderer consequently loads/builds them on first use during gameplay. An additional fixed-clock copied-island load/menu control records further states. Append only their measured S, R and C rows, preserving the original route. No shader machine code or personal save data belongs in these lists.
The existing general startup warmer deduplicates normalized keys, filters stale shader-map keys, builds before the first frame and claims the results into the live shader/render/compute caches. The normal per-device pso_user.tsv learning remains enabled for scenes not in the seed. No Metal 4 archive or all-pairs prebuild is enabled. These content keys work across supported Apple GPUs; each device compiles its own pipelines.

Coverage validation
validation/shader-prewarm/WarmCoverage.m includes the production nvn_mtl.m and uses real shader loading, warm_prepare, warm_claim and exact live cache keys. Compile it using the t_pso_warm Makefile command, replacing the test source and binary, and adding -I<source>/dm/gfx/nvn. Link the other NVN/texture/host stubs exactly as that target does. Game libraries and shader-map data must remain in an external NSP work/build directory. Set DM_NVN_SHMAP to the profile shader_map.tsv and DM_MSL_DIR to the parent containing b-<DMSH_CHAIN>. Invoke: warm-coverage <seed.tsv> <learned.tsv> <report.json>. Run the before/after manifests in alternating order and inspect RED errors, stale keys, skipped specialized states and live-cache misses. This probe measures preparation plus map loading and cache claims in a separate process, with the machine's existing Metal cache. It is not a cold install, game loop or physical device measurement.
The current 198 new rows are 103 shader rows, 92 render pipeline states and three compute pipelines. The complete seed has 1,163 raw rows, normalized by the warmer to 520 shader tasks, 463 render pipelines and five compute pipelines. The historical duplicate-state normalization is intentionally retained; no key format or translation-chain version changes.

Copied-island route
RouteProbe.mm is external instrumentation for a native Mac game process. It selects each of six companion pages, requests at most 32 art keys per phase and opens/closes native pockets during DIY, for 180 seconds after player readiness. Run the before and after seeds against separate copies of the same reference island, fresh runtime/user-cache directories, fixed 2026-10-30 04:00 UTC user clocks and the same unchanged host. The test bundle identity is separate, cloud setup is disabled and the original reference tree is fingerprinted before and after. Raw records, logs and game data stay in the NSP work directory. No user cloud folder is selected or modified.
The route records actual presented intervals separately from guest-frame compile logs; only its observed route is covered. A single pair of runs on an already used local M4 cannot establish iPad/M2 cold-install performance, percentage speedups, device memory limits, battery/thermal results or unseen scene coverage. Unknown pipelines can still compile on their first use and enter the device's learned list for later launches. The first preparation on another GPU or after a system cache eviction may take longer.
